## 1. Общие положения

| Параметр | Значение |
|---|---|
| Протокол | HTTPS (п. 4.4.8 ТЗ) |
| Стиль | REST |
| Базовый адрес | `https://<сервер>/api/v1` |
| Формат данных | JSON, кодировка UTF-8, заголовок `Content-Type: application/json` |
| Аутентификация | Токен в заголовке `Authorization: Bearer <token>`, срок действия 24 часа |
| Даты | ISO 8601, `YYYY-MM-DD` (дата записи), `YYYY-MM-DDTHH:MM:SSZ` (служебные метки времени) |
| Денежные суммы | Рубли, число с двумя знаками после запятой (`1250.50`). В БД — `NUMERIC(10,2)` |
| Пробег | Целое число, км |
| Объём топлива | Литры, число с двумя знаками после запятой |
| Имена полей | `snake_case` |

Все методы, кроме регистрации, входа и проверки доступности, требуют токен. При каждом запросе сервер проверяет, что автомобиль и записи принадлежат текущему пользователю (п. 4.4.8). Если объект принадлежит другому пользователю, сервер отвечает `404`, как будто объекта нет: так не раскрывается сам факт его существования.

### 1.1 Коды ответов

| Код | Когда возвращается |
|---|---|
| `200 OK` | Успешное чтение или изменение |
| `201 Created` | Объект создан, в теле — созданный объект |
| `204 No Content` | Объект удалён / выход выполнен, тела нет |
| `400 Bad Request` | Тело запроса не является корректным JSON |
| `401 Unauthorized` | Нет токена, токен просрочен или неверные e-mail / пароль |
| `404 Not Found` | Объект не найден или принадлежит другому пользователю |
| `409 Conflict` | E-mail уже зарегистрирован |
| `422 Unprocessable Entity` | Ошибка проверки данных, в т. ч. контроль пробега |
| `500 Internal Server Error` | Внутренняя ошибка сервера (событие пишется в журнал, п. 4.1.5) |
| `503 Service Unavailable` | Сервисный режим, идут технические работы (п. 4.1.4) |

### 1.2 Формат ошибки

Все ошибки возвращаются в одном формате. Сообщения — на русском языке и указывают, какое поле заполнено неверно (п. 4.3.3).

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Проверьте заполнение полей",
    "fields": {
      "mileage": "Пробег должен быть от 78 120 до 78 640 км — между соседними записями",
      "volume": "Укажите объём больше 0"
    }
  }
}
```

| `code` | HTTP | Значение |
|---|---|---|
| `VALIDATION_ERROR` | 422 | Не заполнено обязательное поле, неверный тип или диапазон |
| `MILEAGE_CONFLICT` | 422 | Пробег противоречит соседним записям или начальному пробегу (п. 4.3.1) |
| `INVALID_CREDENTIALS` | 401 | Неверный e-mail или пароль (без уточнения, что именно, п. 4.2 ф. 2) |
| `UNAUTHORIZED` | 401 | Токен отсутствует или просрочен — фронтенд переводит на экран входа |
| `EMAIL_TAKEN` | 409 | Пользователь с таким e-mail уже есть |
| `NOT_FOUND` | 404 | Объект не найден |
| `MAINTENANCE` | 503 | Технические работы, фронтенд показывает сообщение |
| `INTERNAL_ERROR` | 500 | Прочие ошибки сервера |

### 1.3 Постраничный вывод

Методы, возвращающие списки записей, принимают `limit` (по умолчанию 50, максимум 200) и `offset` (по умолчанию 0) и возвращают общее число найденных записей `total_count`.

## 3. Описание методов

### 3.1 Аутентификация

#### 1. `POST /auth/register` — регистрация

Тело запроса:

```json
{
  "email": "ivan.petrov@mail.ru",
  "password": "qwerty123",
  "name": "Иван Петров"
}
```

| Поле | Тип | Обязательно | Правила |
|---|---|---|---|
| `email` | string | да | Корректный e-mail, до 254 символов, уникален без учёта регистра |
| `password` | string | да | Не менее 8 символов. Хранится только хэш bcrypt / Argon2 |
| `name` | string | да | 1–100 символов |

Ответ `201`:

```json
{
  "token": "eyJhbGciOiJIUzI1NiIs...",
  "expires_at": "2026-10-22T15:30:00Z",
  "user": {
    "id": 1,
    "email": "ivan.petrov@mail.ru",
    "name": "Иван Петров",
    "registered_at": "2026-10-21T15:30:00Z"
  }
}
```

Ошибки: `409 EMAIL_TAKEN`, `422 VALIDATION_ERROR`.

#### 2. `POST /auth/login` — вход

Тело запроса: `{ "email": "ivan.petrov@mail.ru", "password": "qwerty123" }`

Ответ `200` — как у регистрации.

Ошибки: `401 INVALID_CREDENTIALS` с сообщением «Неверный e-mail или пароль». Сервер не сообщает, что именно неверно.

#### 3. `POST /auth/logout` — выход

Делает текущий токен недействительным. Ответ `204`.

#### 4. `GET /auth/me` — текущий пользователь

Ответ `200`: объект `user` (см. метод 1). Фронтенд вызывает метод при загрузке приложения, чтобы проверить токен.

### 3.3 Автомобили

Объект «Автомобиль»:

```json
{
  "id": 3,
  "brand": "Lada",
  "model": "Vesta",
  "year": 2019,
  "plate_number": "А123ВС77",
  "vin": "XTAGFL110KY123456",
  "initial_mileage": 45000,
  "current_mileage": 78450,
  "last_record_date": "2026-10-18",
  "repairs_count": 9,
  "refuels_count": 56,
  "created_at": "2025-01-12T09:15:00Z"
}
```

`current_mileage` и `last_record_date` вычисляет сервер по последней записи (п. 4.2 ф. 7). Если записей нет, `current_mileage` = `initial_mileage`, `last_record_date` = `null`.

| Поле | Тип | Обязательно | Правила |
|---|---|---|---|
| `brand` | string | да | 1–50 символов |
| `model` | string | да | 1–50 символов |
| `year` | integer | да | От 1900 до текущего года |
| `plate_number` | string | да | 1–12 символов, хранится без пробелов в верхнем регистре |
| `vin` | string \| null | нет | 17 символов: латинские буквы, кроме I, O, Q, и цифры |
| `initial_mileage` | integer | да | ≥ 0 и не больше пробега самой ранней записи |

#### 7. `GET /cars`

Ответ `200`: массив объектов «Автомобиль», отсортированный по дате добавления. Пользователь видит только свои автомобили (до 10, п. 4.4.2).

#### 8. `POST /cars`

Тело — поля из таблицы выше. Ответ `201` — созданный объект.
Ошибки: `422 VALIDATION_ERROR`, в т. ч. при превышении лимита в 10 автомобилей (`fields.limit`).

#### 9. `GET /cars/{car_id}`

Ответ `200` — объект «Автомобиль». Ошибки: `404 NOT_FOUND`.

#### 10. `PUT /cars/{car_id}`

Тело — все поля автомобиля, ответ `200` — изменённый объект.
Если новый `initial_mileage` больше пробега самой ранней записи — `422 MILEAGE_CONFLICT`.

#### 11. `DELETE /cars/{car_id}`

Удаляет автомобиль и каскадно — все его ремонты и заправки (п. 4.3.2). Ответ `204`.
Подтверждение запрашивает фронтенд до вызова метода (п. 4.4.5).

#### 12. `GET /cars/{car_id}/records` — лента записей

Последние записи обоих журналов для карточки автомобиля, по убыванию даты и пробега.

Параметры: `limit` (по умолчанию 5).

```json
{
  "items": [
    { "type": "refuel", "id": 214, "date": "2026-10-18", "mileage": 78450, "title": "Лукойл, АИ-95, 38,40 л", "category": "полный бак", "amount": 2265.60 },
    { "type": "repair", "id": 41, "date": "2026-10-02", "mileage": 77980, "title": "ТО-6: замена масла и фильтров", "category": "ТО", "amount": 8900.00 }
  ]
}
```

`category` — для ремонта название категории, для заправки «полный бак» или «долив».

#### 13. `GET /cars/{car_id}/mileage-range` — допустимый пробег

Помогает фронтенду подсказать пользователю допустимый пробег до отправки формы. Окончательная проверка всё равно выполняется на сервере при сохранении.

Параметры: `date` (обязательный), `exclude_type` и `exclude_id` (необязательные — при редактировании исключают саму запись).

```json
{ "date": "2026-10-10", "min": 77980, "max": 78450 }
```

`max` = `null`, если более поздних записей нет.

### 3.4 Журнал ремонтов

Объект «Ремонт»:

```json
{
  "id": 41,
  "car_id": 3,
  "date": "2026-10-02",
  "mileage": 77980,
  "category": { "id": 1, "name": "ТО" },
  "description": "ТО-6: замена масла и фильтров",
  "place": "СТО «Мотор» на Варшавке",
  "labor_cost": 2500.00,
  "parts_cost": 6400.00,
  "total_cost": 8900.00
}
```

| Поле | Тип | Обязательно | Правила |
|---|---|---|---|
| `date` | string (date) | да | Не позже текущей даты |
| `mileage` | integer | да | Контроль пробега (п. 4.3.1) |
| `category_id` | integer | да | Существующий id из справочника |
| `description` | string | да | 1–1000 символов |
| `place` | string | нет | До 200 символов |
| `labor_cost` | number | да | ≥ 0 |
| `parts_cost` | number | да | ≥ 0 |

`total_cost` = `labor_cost` + `parts_cost`, вычисляет сервер.

#### 14. `GET /cars/{car_id}/repairs` — журнал и поиск

Один метод обслуживает и журнал ремонтов (ф. 5), и поиск (ф. 8). Без параметров возвращает весь журнал.

| Параметр | Тип | Назначение |
|---|---|---|
| `q` | string | Поиск по тексту описания и места, без учёта регистра |
| `category_id` | integer | Категория работ |
| `date_from`, `date_to` | date | Период, границы включительно |
| `mileage_from`, `mileage_to` | integer | Диапазон пробега, включительно |
| `sort` | string | `date_desc` (по умолчанию), `date_asc`, `cost_desc` |
| `limit`, `offset` | integer | Постраничный вывод |

Пример: `GET /cars/3/repairs?q=колодки&date_from=2025-01-01&date_to=2026-10-21`

```json
{
  "items": [ { "id": 37, "date": "2026-04-19", "mileage": 71200, "category": { "id": 4, "name": "Тормозная система" }, "description": "Замена передних тормозных колодок", "place": "СТО «Мотор» на Варшавке", "labor_cost": 1200.00, "parts_cost": 3100.00, "total_cost": 4300.00 } ],
  "total_count": 1,
  "sum": { "labor_cost": 1200.00, "parts_cost": 3100.00, "total_cost": 4300.00 }
}
```

`sum` считается по **всем** найденным записям, а не только по текущей странице.

#### 15. `POST /cars/{car_id}/repairs`

Тело — поля из таблицы. Ответ `201` — объект «Ремонт».
Ошибки: `422 VALIDATION_ERROR`, `422 MILEAGE_CONFLICT`, `404 NOT_FOUND`.

#### 16. `GET /cars/{car_id}/repairs/{repair_id}` — ответ `200`, объект «Ремонт».

#### 17. `PUT /cars/{car_id}/repairs/{repair_id}` — тело как при создании, ответ `200`.

#### 18. `DELETE /cars/{car_id}/repairs/{repair_id}` — ответ `204`.

### 3.5 Журнал заправок

Объект «Заправка»:

```json
{
  "id": 214,
  "car_id": 3,
  "date": "2026-10-18",
  "mileage": 78450,
  "station": "Лукойл, Каширское ш., 61",
  "fuel_type": { "id": 2, "name": "АИ-95" },
  "volume": 38.40,
  "price_per_liter": 59.00,
  "amount": 2265.60,
  "full_tank": true
}
```

| Поле | Тип | Обязательно | Правила |
|---|---|---|---|
| `date` | string (date) | да | Не позже текущей даты |
| `mileage` | integer | да | Контроль пробега (п. 4.3.1) |
| `fuel_type_id` | integer | да | Существующий id из справочника |
| `station` | string | нет | До 200 символов |
| `volume` | number | да | > 0, до 500 |
| `price_per_liter` | number | да | > 0 |
| `full_tank` | boolean | нет | По умолчанию `false` |

`amount` = round(`volume` × `price_per_liter`, 2) — вычисляет сервер (п. 4.3.1). Фронтенд показывает ту же сумму в форме до сохранения, но в запросе её не передаёт.

#### 19. `GET /cars/{car_id}/refuels`

Параметры: `date_from`, `date_to`, `fuel_type_id`, `sort` (`date_desc` по умолчанию), `limit`, `offset`.

```json
{
  "items": [ { "id": 214, "date": "2026-10-18", "mileage": 78450, "station": "Лукойл, Каширское ш., 61", "fuel_type": { "id": 2, "name": "АИ-95" }, "volume": 38.40, "price_per_liter": 59.00, "amount": 2265.60, "full_tank": true } ],
  "total_count": 56,
  "sum": { "volume": 2104.50, "amount": 118640.30 }
}
```

#### 20. `POST /cars/{car_id}/refuels`

Тело — поля из таблицы. Ответ `201` — объект «Заправка».
Ошибки: `422 VALIDATION_ERROR`, `422 MILEAGE_CONFLICT`.

#### 21. `GET /cars/{car_id}/refuels/{refuel_id}` — ответ `200`.

#### 22. `PUT /cars/{car_id}/refuels/{refuel_id}` — тело как при создании, ответ `200`.

#### 23. `DELETE /cars/{car_id}/refuels/{refuel_id}` — ответ `204`.

### 3.6 Итоги

#### 24. `GET /cars/{car_id}/summary`

Параметры: `date_from`, `date_to` — границы периода включительно. Без параметров — весь период эксплуатации.

```json
{
  "car_id": 3,
  "date_from": "2026-01-01",
  "date_to": "2026-10-21",
  "repairs_total": 38700.00,
  "fuel_total": 71240.80,
  "total": 109940.80,
  "fuel_volume": 1208.40,
  "distance": 15430,
  "avg_consumption": 7.84,
  "cost_per_km": 7.12,
  "by_category": [
    { "category": { "id": 1, "name": "ТО" }, "total": 17800.00, "count": 2 },
    { "category": { "id": 4, "name": "Тормозная система" }, "total": 4300.00, "count": 1 }
  ],
  "by_month": [
    { "month": "2026-01", "repairs": 0.00, "fuel": 6930.50 },
    { "month": "2026-02", "repairs": 12400.00, "fuel": 6512.00 }
  ]
}
```

Правила расчёта (п. 4.3.1):

- `repairs_total` — сумма `total_cost` ремонтов с датой в границах периода;
- `fuel_total` — сумма `amount` заправок с датой в границах периода;
- `total` = `repairs_total` + `fuel_total`;
- `distance` — разница между наибольшим и наименьшим пробегом записей периода;
- `avg_consumption` = (ΣV / ΔL) × 100, л/100 км, где ΣV — объём заправок после первой заправки «до полного бака» периода до последней такой заправки включительно, ΔL — пробег между ними. Если заправок «до полного бака» меньше двух — `null`, фронтенд пишет «Недостаточно данных»;
- `cost_per_km` = `total` / `distance`, `null` при `distance` = 0.

Время ответа — не более 3 секунд для всего периода (п. 4.2).

### 3.7 Служебные методы

#### 25. `GET /health`

Без авторизации. Ответ `200`: `{ "status": "ok", "db": "ok", "time": "2026-10-21T15:30:00Z" }`.

## 5. Поведение фронтенда при ошибках

| Ответ | Что видит пользователь |
|---|---|
| `401 UNAUTHORIZED` | Переход на экран входа с сообщением «Сеанс завершён, войдите снова» |
| `422` с `fields` | Поля подсвечиваются, под каждым — текст из `fields` |
| `404` | «Запись не найдена — возможно, она уже удалена» и возврат к списку |
| `503 MAINTENANCE` | Полоса вверху экрана: «Идут технические работы. Данные сохранены, попробуйте позже» |
| `500`, нет сети | «Не удалось сохранить. Проверьте подключение и повторите» — введённые данные в форме не сбрасываются |

## 6. Договорённости, от которых зависит работа фронтенда

Проверить их все сразу можно скриптом `tools/check_api.py` (74 проверки по этому документу):

```bash
python3 tools/check_api.py --base http://127.0.0.1:8000/api/v1
```

1. Адреса, имена полей и коды ответов — строго как в разделах 2–3. Поля в `snake_case`.
2. Ошибки — всегда JSON в формате п. 1.2, включая 401, 404, 409, 422 и 503. Ключи `error.fields` совпадают с именами полей запроса (`mileage`, `volume`, `email` и т. д.) — по ним фронтенд подсвечивает поле.
3. Токен возвращается в поле `token` ответа на вход и регистрацию, дальше передаётся в заголовке `Authorization: Bearer <token>`. Куки не используются.
4. Суммы и объёмы можно отдавать числом или строкой (`2265.60` или `"2265.60"`) — фронтенд принимает оба варианта. Пробег — целым числом.
5. `id` может быть числом или строкой (например, UUID).
6. Суммы (`amount`, `total_cost`, итоги) считает сервер; фронтенд показывает их как есть.
7. Если API открывается с другого домена, чем сайт, сервер разрешает CORS для адреса сайта, методов `GET, POST, PUT, DELETE` и заголовков `Authorization, Content-Type`. При выкладке через `deploy/nginx.conf` сайт и API на одном адресе, CORS не нужен.
